RepoSpector privacy policy

Effective 23 November 2026. Applies to the RepoSpector Chrome extension.

In short

RepoSpector has no server. It does not collect analytics, usage data or crash reports, and it has no account. Your code goes from your git host to your browser, and from your browser only to the AI model provider you choose. Everything RepoSpector keeps stays on your device until you delete it.

What is sent, and where

Your git host (GitHub or GitLab)
The extension reads pull request details, diffs and, when you ask where code is used, a download of the repository at the reviewed commit, from the hosts you add in settings. It uses your access token if you saved one. When you choose to post, it creates draft comments (a pending review on GitHub, draft notes on GitLab) on that pull request, visible only to you until you publish them there.
The model provider you choose (Anthropic, OpenAI or Google)
To review a pull request, the extension sends that pull request's title and diff, and then the review's findings, to the provider of the model you picked, using your own API key. Strings that look like secrets (API keys, tokens, private keys) are masked before sending. Each provider's own terms and privacy policy govern what they do with requests; RepoSpector does not send them anything else. If you pick Ollama, the review runs on your own computer and nothing goes to a model provider.
Hugging Face (only if you turn on meaning-based matching)
The model is downloaded once from huggingface.co, a fixed version whose files are checked before they are saved. Nothing of yours is sent to Hugging Face; matching runs on your device.
A program on your computer (only if you turn on local mode)
The extension asks the RepoSpector program you installed on your computer where code is used, sending the repository name, the commit and the finding locations. The program reads only the clones you listed when installing it, and keeps its index in its own cache folder. This stays on your computer.

Nothing is sent anywhere else. There are no third-party scripts, trackers or advertising.

What is stored on your device

  • Keys and access tokens, encrypted with your passphrase (PBKDF2-SHA-256, 600,000 iterations, AES-GCM) in Chrome's extension storage; the passphrase itself is never stored. In memory-only mode they are kept until Chrome closes and never written to disk. Each key is sent only to its own service.
  • Reviews: the findings, model, cost and status of your last 50 reviews. A review's diff is kept only while it runs, so an interrupted review can resume, and is deleted when it finishes.
  • Your feedback (Useful, Not useful, Not relevant here, and any reason you type), with the finding's text, file and repository. It is used to lower similar findings in later reviews. It leaves your device only if you export it.
  • The saved code index: names and line positions of functions and classes for the last 20 commits you indexed. Never your code.
  • The matching model, if you turned on meaning-based matching (about 22 MB). Turning the setting off deletes it.
  • Settings: the hosts you added and the model you chose.

You can delete feedback, saved indexes and keys in settings. Removing the extension deletes everything it stored.

Permissions

Side panel, storage, offscreen
Show the review next to the page, keep the data above, and let a review keep running when the panel is closed.
Scripting
Place small "RS" markers beside the lines that have findings, on pull request pages of hosts you added. The marker script reads only where lines are on the page, holds no keys and sends nothing.
Access to specific sites (asked for at the time you need it)
Each git host you add and its API; the API of the model provider you choose; codeload.github.com for repository downloads from GitHub; localhost for Ollama. (The meaning-based matching model downloads from huggingface.co without any extra permission.)
Native messaging (asked for only if you turn on local mode)
Talk to the RepoSpector program installed on your computer.

Children

RepoSpector is a developer tool and is not directed at children.

Changes

If this policy changes, the new version ships with the extension update, with a new effective date at the top.
