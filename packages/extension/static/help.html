RepoSpector help

RepoSpector reviews GitHub pull requests and GitLab merge requests with the AI model you choose, using your own key. It runs in your browser; there is no RepoSpector server.

Get started

  1. Open RepoSpector's settings (right-click the toolbar icon, then Options).
  2. Under Git hosts, add GitHub or GitLab (for example https://github.com). Chrome asks you to allow that site.
  3. Under Keys and access tokens, choose a passphrase. Your keys are encrypted with it on this device. Or keep keys in memory only, until Chrome closes.
  4. Under Model, pick a provider and a preset (Best accuracy, Balanced or Low cost), or Ollama to run on your own computer. Add that provider's API key and press Test key.
  5. Optional: add an access token for your git host. You need one to review private repositories and to post drafts. The settings page links to the host's token page with the right scopes filled in.
  6. Open a pull request, click the RepoSpector icon to open the side panel, check the estimated cost, and press Review this pull request. You can close the panel; the review keeps running.

Reading a review

Each finding shows its file and line, what goes wrong, and a label from a second check:

Verified
A second pass tried to disprove the finding and could not.
Suspected
The second pass found evidence against it, or your team marked similar findings as not useful. The reason is shown. Suspected findings are kept, listed last, because some are still real.
Not checked
The second pass's answer could not be read.

Findings are ordered by how likely they are to be real defects. On our test set, the first finding was a real bug about 70% of the time, so reading from the top pays off.

Posting drafts

Tick the findings you want and press Post … as a draft review. On GitHub this creates a pending review, on GitLab draft notes. Only you can see them until you submit or publish them on the site, so you can edit or delete any of them first.

  • RepoSpector will not post if the pull request has new commits since the review, because the lines would be off. Review again first.
  • Findings already on the pull request are not posted twice.
  • Tokens need write access to pull requests: on GitHub a classic token with repo, or a fine-grained token with Pull requests: Read and write; on GitLab the api scope. Test token in settings tells you whether yours can post.

Feedback

Mark findings Useful, Not useful or Not relevant here, with an optional reason. In later reviews, a finding you marked not useful, or one similar to three or more you marked not useful, is labelled suspected and moved down. Nothing is hidden.

Similar means sharing most of their words. In settings you can turn on meaning-based matching, which also catches the same point worded differently. It downloads a small model (22 MB) once from Hugging Face and runs on your device. It is approximate: in our tests it caught most reworded comments, and occasionally matched a different problem in the same area. Matches only lower a finding; they never hide it.

Feedback stays on your device. To share it with your team, use Export as JSONL in settings and commit the file as .RepoSpector/feedback.jsonl.

Where code is used

After a review, Show where this code is used downloads the repository at the reviewed commit and indexes it on your device. Each finding then shows the function or class it is in, who calls it, and its subclasses, with links to the exact lines. Nothing is sent to the model.

  • The index is saved on your device. The same commit opens instantly next time; after a new push only changed files are read again.
  • Callers are matched by name, so a list can include unrelated code that happens to share the name.
  • Supported languages: Python, Go, Java, Ruby, JavaScript, TypeScript.
  • Repositories over 300 MB (compressed) are not downloaded. Use local mode for those.

On pull request pages, findings are also marked beside their lines with a small RS badge (teal: verified, grey: other). Hover it to read the finding.

Local mode

If the repository is cloned on your computer, RepoSpector can ask its local program for the index instead of downloading the repository. It reads only the folders you list.

  1. Install Node.js 22 or later.
  2. Install the program: npm install -g repospector-mcp@0.7.0 (a global install, because Chrome starts it from a fixed path).
  3. Register it: repospector-mcp native install --extension-id <id> --repo /path/to/your/clone. Settings shows the exact command with this extension's id. Add more clones later with repospector-mcp native add-repo <path>.
  4. In settings, turn on Local mode. Chrome asks to allow communication with the program.

The local copy must contain the reviewed commit (run git fetch first). If it doesn't, the panel says so and offers the download instead. Works on macOS and Linux; on Windows the program must be registered by hand.

Cost

Before each review the panel shows an estimated cost range, from the size of the change and the model's published price (the date of the prices is shown). After the review it shows what was actually used. You pay your provider directly. Ollama has no model cost.

Fixing problems

"Your keys are locked"
Open settings and enter your passphrase. Keys stay unlocked until Chrome closes.
"Could not read this pull request (404)"
The repository is private or the token cannot see it. Add or replace the access token for that host in settings.
Ollama: the review fails to reach the model
Ollama refuses browser extensions unless you allow them. Set the environment variable OLLAMA_ORIGINS to chrome-extension://* and restart Ollama.
"You already have a pending review on this pull request"
GitHub allows one pending review per person. Submit or discard it on GitHub, then post again.
"The pull request has new commits since this review"
Press Review again, then post.
"This review stopped…"
Chrome closed the background page that runs reviews. Press Resume review; finished steps are not paid for again.
No RS markers on the page
Open the Files changed tab (Changes on GitLab) and expand collapsed files. GitLab markers depend on GitLab's page layout and may not appear on every version.
